2. ROOT CAUSE (code-level; one class, two sites)
------------------------------------------------
Both sites produce a drive-relative path ("/Users/...") from an absolute
windows path and hand it to an API that resolves it against the process's
CURRENT DRIVE. Locally everything lives on C: so the bug is invisible; on the
runner cwd is D:\a\LSE\LSE and the resolved location is on the wrong volume.

  (a) src/communication/socket.cpp unix_address(): Endpoint::parse splits
      "unix://C:/Users/.../x.sock" at the first '/' -> authority "C:", path
      "/Users/.../x.sock". unix_address() memcpy'd ONLY path into sun_path
      (drive dropped) -> bind() targets D:\Users\... -> fails -> all 9
      pipe-URL tests die at ln.ok().
  (b) src/hub/cache.cpp scan(): LSE_MODEL_DIRS split unconditionally on ':'
      -> "C:\Users\...\models" became tokens "C" and "\Users\...\models";
      the second resolves to D:\Users\...\models -> not found -> the local
      checkpoint contributes 0 models -> 2 instead of 3.
