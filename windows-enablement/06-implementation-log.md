## 4. Directive deviations (deliberate, each documented in-code)

These are places where the directive/plan could not be followed literally on
Windows; the repo reality won and the deviation is recorded per governance.

1. **WSAPoll timeout granularity is milliseconds**, not epoll's nanoseconds.
   `poller_winsock.cpp` rounds the ns timeout **up** and clamps to `0x7FFFFFFF`
   ms. Documented in the file header.
2. **`Poller::fd()` returns the wake socket on Windows.** WSAPoll has no
   waitable fd of its own, so a self-connected UDP loopback socket is the wake
   mechanism and `epoll_fd_` *aliases* `wake_fd_` (the dtor closes once).
   `reactor.cpp` pushes `poller.fd()` into a `wait_fds` set with zero consumers,
   so the aliasing is inert; documented.
3. **New header member `interests_` in `poller.hpp`** (`[[maybe_unused]]
   std::map<int, Interest>`). WSAPoll rebuilds its wait set every call, so the
   winsock poller tracks per-fd interest; epoll/kqueue leave it empty. Follows
   the existing `wake_fd_` `[[maybe_unused]]` precedent; no POSIX effect.
4. **`heap_stats()` returns zeros on Windows.** The UCRT has no `mallinfo2`
   analogue; `api/lse.cpp`'s `host_memory_json` reports the (zeroed) heap fields
   with unchanged JSON keys, and `malloc_trim` becomes a no-op (`relieved = 0`,
   the UCRT decommits on its own).
5. **`comm_nap_ns` uses `Sleep`**, capped at `0xfffffffe` ms because
   `Sleep(INFINITE)` never returns.
6. **`QueryInterruptTime` resolved via `GetProcAddress`.** Recent SDKs *declare*
   the biased `QueryInterruptTime` (the `CLOCK_BOOTTIME` analog) in
   `<realtimeapiset.h>` but `kernel32.lib` ships only the **`Unbiased`** import
   thunk (verified with `dumpbin /LINKERMEMBER`), so a direct call left
   `__imp_QueryInterruptTime` unresolved. `kernel32.dll` still exports it, so
   `now_boottime_ns` resolves it at runtime and falls back to the unbiased
   counter. Not a directive item — discovered during M2a link.
7. **`windows`-crate raw-dylib stubs dropped from the Rust native-lib list.**
   `cargo … --print native-static-libs` on Windows emits bare `foo.lib` tokens
   including synthetic `windows.0.53.0.lib` / `windows.0.52.0.lib` raw-dylib
   stubs. Those are materialized only during a *rustc-driven* link; a
   `cargo build --lib` staticlib never links, so no such file exists for
   `lld-link` to open. `LSERust.cmake` filters `^windows\.[0-9]` and keeps the
   real system import libs (which resolve and cover the same DLLs). Verified:
   both executables link with the stubs removed.
8. **HRX backend forced OFF on Windows** (per the program plan) — so every
   `if(NOT TARGET lse_backend_hrx)` path is the live one, and the loomc/hipc TUs
   are compiled directly into the tests rather than arriving via `lse_backend_hrx`.

## 5. Discrepancy log (artifacts 01–05 vs. repo/toolchain reality)

Recorded per the governance rule "trust the repo over the directive and note the
discrepancy." Grouped by theme.

**Build system / flags**
1. **S1's "`-fno-fast-math` accepted as-is" is wrong.** clang-cl's MSVC mode
   rejects the GNU-spelled flag; the Windows flag branch uses the MSVC/clang-cl
   spelling and `_CRT_NONSTDC_NO_DEPRECATE` / `_CRT_SECURE_NO_WARNINGS`
   (ID-9), with `-ffp-contract=off` per ID-14.
2. **`-Wall` ≠ intended coverage.** Under clang-cl, `-Wall` maps to
   `-Weverything` (unusable noise). WP0 probe chose `/clang:-Wall` deliberately;
   the arch-header designated-initializer warnings and a few upstream
   sign-conversion warnings were left as-is (not ours to fix; see §7).
3. **CMake 3.31 C++26 dialect gap.** 3.31.9 does not fully model `CXX26`; a
   dialect override was needed to get `-std=c++26`-equivalent under clang-cl.

**Platform-shim surface missed by the S2 census** (each found only at compile
time; all routed through `lse::platform`):
4. **`fsync`** (`hub/pull.cpp:508`) — missed by *every* census grep →
   `platform::sync_fd`. Lesson logged: census patterns must include
   `fsync`/`fdatasync`.
5. **`fnmatch`** (`hub/pull.cpp`) → `platform::glob_match`.
6. **`isatty`** (`hub/pull.cpp`) → `platform::is_tty`.
7. **`std::aligned_alloc`** (`backends/cpu/cpu_backend.cpp`) — absent from the
   MSVC STL → `_aligned_malloc`/`_aligned_free`, paired on all three sites
   (alloc, `shared_ptr` deleter, legacy free). Missed by the S2 inventory.

**UCRT / MSVC-STL facts (not in the artifacts)**
8. **`struct stat::st_ino` is always 0** and there is no ns-resolution mtime →
   `hub/cache.cpp` dedup uses `platform::file_stamp_of_path`
   (`GetFileInformationByHandle`: dev/ino/size/mtime), else every hard link
   collapses to one identity.
9. **`<io.h>` has no POSIX `pipe`** (only `_pipe`); it *does* have
   read/write/close/dup/dup2 → `api/lse.cpp` uses `platform::make_pipe`.
10. **No `malloc_trim`, no `mallinfo2`** in the UCRT (see §4.4).
11. **`fs::path::c_str()` is `wchar_t*`** — five `%s` hazard sites would print
    garbage; all converted to `.string().c_str()` (hub/cli.cpp and others).
12. **`api/lse.cpp` is in the global namespace** (no `namespace lse`), so every
    shim call there must be qualified `lse::platform::`.

**Rust / FFI**
13. **`ring` builds without NASM** on this host (no assembler needed for the
    x86_64 MSVC target path used here).
14. **`native-static-libs` are bare `.lib` tokens** on Windows (not `-lfoo`), and
    include the un-materializable raw-dylib stubs (see §4.7). Fallback set for a
    failed query: `ws2_32.lib bcrypt.lib userenv.lib`.
15. **`weights.cpp` closes its fd right after `mmap`** — on Windows a mapped view
    dies with its section handle, so the shim keeps a process-wide registry of
    section+file handles keyed by the view pointer, released at `file_unmap`.

**Sockets / comm**
16. **`rename` → `ENOTEMPTY` mapping** differs from POSIX; handled in the shim.
17. **`SOCK_NONBLOCK` / `SOCK_CLOEXEC` are synthetic** on Winsock — the shim
    strips them (`0x20000000` / `0x40000000`) and applies `ioctlsocket(FIONBIO)`
    (needs `static_cast<long>(FIONBIO)`; the SDK macro is unsigned).
18. **Abstract UNIX-socket namespace is Linux-only** → `socket.cpp` returns
    `kUnimplemented` on Windows, mirroring the existing `__APPLE__` guard.
19. **`sendmsg`** → `WSASendMsg`; **`MSG_NOSIGNAL` ≡ 0**; **`SHUT_WR` →
    `SD_SEND`**; `WSAGetLastError` → `errno` translation table in
    `winsock_compat.cpp`; `getsockopt(SO_ERROR)` converts the returned `WSA*`
    value to its errno equivalent.
20. **httplib keeps its `select` default on Windows** (`CPPHTTPLIB_USE_POLL`
    guarded `#ifndef _WIN32`); Windows `FD_SETSIZE` counts *sockets in the set*,
    not descriptor values, so the 64-socket capacity is a socket-count limit.
21. **Zero-macro socket seam.** `winsock_compat.hpp` gives `lse::comm` one
    `sock_*` inline wrapper per call (POSIX side = exact `::` pass-throughs). No
    function-like macros over POSIX names, because `#define close(x)` would also
    rewrite member declarations like `StreamLink::close()`.

**Graph / core portability**
22. **`__builtin_memcpy` → `std::memcpy`** (+ explicit `<cstring>`) in
    `hash.hpp`, `dtype.hpp`, `graph.cpp`: the GNU/Clang builtin is not portable
    to the MSVC-STL include graph and the files relied on transitive includes.
    Identical codegen on POSIX. (`hip_emitter.cpp:290` left as-is — HRX-scoped,
    out of Phase-1 per 02-program-plan.)
23. **`ModelPaths.weights` is `std::string`**, not `fs::path` (affected a
    `%s`/`.c_str()` site).
24. **`test_runtime` does not link `lse_kernels`** (only `test_perplexity` does),
    so with HRX off nothing pulls the archive in and its self-registered
    primitives (`softmax_top.*`) never reach the binary — the `softmax_top` case
    failed with `not_found`. Pre-existing latent `!hrx` gap (masked on Linux CI
    where `lse_backend_hrx` supplies `lse_kernels`), **not** a porting
    regression. Fixed additively: `target_link_libraries(test_runtime PRIVATE
    lse_kernels)` inside the `if(NOT TARGET lse_backend_hrx)` branch — HRX-off
    only, `lse_force_load` makes the WHOLEARCHIVE sticky. `test_runtime` now
    passes.
25. **`Json != std::string_view` ambiguity** under the MSVC STL required
    disambiguating to `!= Json(k)` at the affected sites.
26. **Test-file POSIX-include count = 15** (ID-14's correction of S1's "19"):
    17 files include `<unistd.h>`/`<sys/wait.h>`, minus the 2 HRX-gated
    (`test_jit.cpp`, `test_capture_prefill.cpp`) that never build on Windows.
