**Invariants binding on every command below (B-1 lesson):**

- **I-1 — No silent degeneration.** Every pipeline that feeds a test-name regex or a count assertion must run under `set -euo pipefail`, and every ctest invocation must assert **both** `100% tests passed` **and** `out of N` with `N == expected` (a 1/1 pass is a failure of the gate, not a pass).

- **I-4 — Zero Linux behavior change.** All test-side edits are `#ifdef _WIN32`/`if(WIN32)`-guarded or test-only portable rewrites sanctioned by 04 §6 P5.

### 3.2 `tests/compat.hpp` design — with a verified correction to 04 §6 P1

**Design defect found by verification:** P1 claims including `compat.hpp` from `tests/harness.hpp` "fixes 14 of 15 unistd files without touching them". That is mechanically impossible: those files contain a literal `#include <unistd.h>` line, and no pre-existing macro can satisfy an include of a **nonexistent** header — the compile fails at the directive regardless of what `harness.hpp` defined. The zero-touch mechanism that does work is a **shim include directory**:

```
tests/compat.hpp            # the real content (below)
tests/compat/unistd.h       # #pragma once → #include "../compat.hpp" (+ <io.h>, <process.h>)
tests/compat/sys/wait.h     # #pragma once → pid_t, WIFEXITED/WEXITSTATUS over GetExitCodeProcess results
```

Wiring (additive, POSIX-inert): inside `lse_add_test()` in `tests/CMakeLists.txt`, one guarded line
`if(WIN32) target_include_directories(${name} PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/compat) endif()`;
plus the same guarded `target_include_directories` on the raw `test_server_shutdown` target. `compat/` sorts into the include path only on Windows; on POSIX the real `<unistd.h>` wins because the directory is never added. **All 14 harness-based files then compile with ZERO file edits.** Record this as a deviation-from-04 refinement in the WP12a commit message and STATUS.md (repo reality over artifact text — 06's governance rule).

`tests/compat.hpp` content (all verified-needed against the per-file symbol census in §3.3):
`getpid`→`_getpid`; `setenv/unsetenv`→`_putenv_s` wrappers; `usleep`→`Sleep(ms)` (round up, documented ms granularity per 06 §4.1); `access`→`_access`; `mkdtemp`→ inline over `GetTempPathW`+`_mkdir` retry loop (or `lse::platform::make_temp_dir` — compat.hpp may include `lse/core/platform.hpp`); `ssize_t` typedef if absent; `STDIN/STDOUT/STDERR_FILENO` = 0/1/2; `pid_t` typedef. Header doc comment lists every semantic delta (R8 pattern).

**fork/waitpid doctrine (binding):** no fork emulation, anywhere — Windows has no safe address-space-copy primitive, and `test_server_shutdown`'s case *depends* on fork semantics (lock-free child inheritance). Tests needing process semantics port to **CreateProcess self-relaunch** (`--child-stuck` argv mode) + `_pipe` + `GetExitCodeProcess` (S4 §6 P2). SIGTERM is undeliverable (06: `SetConsoleCtrlHandler` path) → the stuck-child case asserts exit-code-1 + marker-read-empty, not signal delivery. Anything the census exposes that cannot be re-expressed this way → `#ifdef _WIN32 LSE_SKIP("windows: <capability> — #<issue> — review-by <date>")` + K-entry (§4) — **last resort, K-budget-governed, never silent**.

## 4. K-ledger (runtime quarantine) — format, counting, consumption

**File:** `windows-enablement/K-LEDGER.md` (created by C2-WP3; L3 machine-readable). Header comment **freezes the row pattern** (A-6): data rows begin `` | ` `` (pipe-space-backtick); the header row does not; `|---` separators do not.

**Row format (one line per entry, exact):**

```
| `binary:case-group` | windows: <capability|flake> — <one-line platform delta> | #<issue> | <review-by YYYY-MM-DD, ≤ 90d> |
```

**K count (fixes the M-4 header-row bug — `grep -c "^| "` counted the header):**

```bash
K=$(grep -cE '^\| `' windows-enablement/K-LEDGER.md || true)   # validated pattern: only data rows start "| `"
[ "$K" -le 5 ] || { echo "G-C2-4 FAIL: K=$K > 5"; exit 1; }
```

**Rules (ID-6/BL-4):** K ≤ 5 at M3; every entry is a platform-capability gap or quarantined flake — **never a product defect**; **zero bucket-(a) entries ever**; every entry has an upstream issue (PR7 containment) and a review-by date ≤ 90 days. K counts **case groups inside passing binaries** (`LSE_SKIP` keeps exit 0 — verified in `harness.hpp:run_all`), so **K never reduces W**.

**How ctest consumes it:**
- *Case-group entries (the norm):* implemented as `#ifdef _WIN32 LSE_SKIP("windows: … — #N — review-by …")` in the test source; the ledger row mirrors the skip string (same `binary:case-group` key). ctest needs no exclusion — the binary passes with printed skips. Verification: total skips across the run ≤ K-budget is checked by scraping `skip … (windows:` lines from `logs/m3-ctest-windows.txt` and asserting the distinct `binary:case-group` count == ledger K.
- *Binary-level entries (exceptional; only for harness-less binaries that cannot be ported):* generator (never hand-typed):
  `KEX=$(awk -F'|' '/^\| `/{gsub(/[` ]/,"",$2); if ($2 !~ /:/) print $2}' windows-enablement/K-LEDGER.md | paste -sd'|' -)` → run `ctest -E "^($KEX)$"` and assert `W_run == W − |K_bin|` in the gate arithmetic; the binary-level row additionally carries the KNOWN_FAILURES-free mechanism note (a Windows entry there is forbidden — I-5).

**X vs K separation (BL-4), restated for the implementer:**

| | X (compile) | K (runtime) |
|---|---|---|
| Ledger | `COMPILE_EXCLUSIONS.md` | `K-LEDGER.md` |
| Mechanism | `if(NOT WIN32)` in `tests/CMakeLists.txt` (configure-time; test never registered) | `#ifdef _WIN32 LSE_SKIP` in-test (binary passes; case group skipped) |
| Effect on W | **reduces W** | **never reduces W** |
| M3 target | **X = 0** | **K ≤ 5** |
| Cross-contamination | a compile failure may NEVER be absorbed by K or KNOWN_FAILURES.md | a runtime failure may NEVER be absorbed by X |
